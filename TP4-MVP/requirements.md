# Requisitos do MVP - Trabalho Prático IV

Este documento detalha os requisitos para o Produto Mínimo Viável (MVP) do Trabalho Prático IV, conforme especificado no enunciado [1]. O objetivo é desenvolver uma versão funcional e navegável do aplicativo escolhido, demonstrando a proposta do produto e validando o conceito da solução.

## 1. O que é o MVP?

O MVP é uma versão funcional do sistema que permite validar o conceito do aplicativo, garantir coerência com os artefatos produzidos nas etapas anteriores e demonstrar a solução de forma funcional [1].

### Objetivos do MVP:
- **Validar Conceito**: Confirmar que a proposta do aplicativo resolve um problema real dos usuários.
- **Coerência com Artefatos**: Garantir alinhamento com os documentos e entregas das etapas anteriores do TP.
- **Demonstração Funcional**: Apresentar uma solução navegável e operacional para avaliação da equipe.

## 2. Desenvolvimento do MVP

A equipe deverá utilizar o Figma Make para geração inicial das telas, componentes e estrutura do sistema. No entanto, o sistema deverá obrigatoriamente ser evoluído e aprimorado pela equipe [1].

### Ponto de Partida:
- Utilizar Figma Make para geração inicial das telas, componentes e estrutura do sistema.

### Requisitos de Evolução:
- Ser evoluído no Visual Studio Code.
- Possuir modificações implementadas pela equipe.
- Apresentar melhorias após a geração inicial.
- Possuir funcionalidades implementadas.
- Demonstrar entendimento técnico do código produzido.

## 3. Requisitos Obrigatórios do MVP

O MVP deve conter no mínimo **8 telas**, sendo três delas obrigatórias com requisitos específicos de implementação [1].

### 3.1. Tela de Cadastro de Usuário

- **Funcionalidade**: Armazenamento de dados do usuário.
- **Validação**: Validação de campos (e.g., formato de e-mail, força da senha).
- **Feedback**: Mensagens de feedback claras para o usuário.
- **Termos e Privacidade**: Exibição e aceite obrigatório dos Termos de Uso e Política de Privacidade.

### 3.2. Tela de Login

- **Autenticação**: Processo de autenticação de usuário.
- **Feedback**: Mensagens de erro e sucesso.
- **Termos e Privacidade**: Acesso aos Termos de Uso e Política de Privacidade.
- **Logo do Aplicativo**: A logo do aplicativo é obrigatória nesta tela.

### 3.3. Outras Telas Essenciais

- **Quantidade**: Mínimo de 6 telas adicionais (totalizando 8 telas).
- **Funcionalidades**: Devem ser funcionalidades essenciais do aplicativo, relacionadas entre si.
- **Navegação**: Navegação implementada entre as telas (menus, botões, acesso sequencial, etc.).

## 4. Rastreabilidade com Histórias de Usuário

Para cada funcionalidade implementada no MVP, deve ser indicada a história de usuário correspondente e uma breve explicação de como ela foi implementada [1].

### Exemplo de História de Usuário e Implementação:

> **História de Usuário:** Enquanto doador em potencial, quero me cadastrar no aplicativo e receber por e-mail um guia com orientações de uso, para iniciar o processo de doação de forma segura e informada.

> **Implementação no MVP:** A funcionalidade foi implementada por meio da tela de cadastro de usuário, onde o doador em potencial pode inserir seus dados obrigatórios: nome completo, e-mail, CEP, CNS (Cartão Nacional de Saúde) e senha.
